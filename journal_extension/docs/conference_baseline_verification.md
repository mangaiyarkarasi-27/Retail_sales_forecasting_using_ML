# Conference Baseline Verification

This document records the verification of the existing conference forecasting baseline and details the origin of the discrepancy between the serialized model performance and the manuscript table.

---

## 1. Dataset Used

* **Source File**: `data/processed_train.csv` (which is preprocessed from `data/train.csv`).
* **Dimensions**: 898,000 rows (913,000 raw rows minus 15,000 rows containing NaNs dropped due to the 30-day lag/rolling feature window).
* **Target Variable**: `sales` (daily sales units per store-item combination).
* **Date Column**: `date`.
* **Identifiers**: `store` (1 to 10) and `item` (1 to 50).

---

## 2. Feature Set

The forecasting features are generated per store-item combination and include:
* **Calendar features**: `year`, `month`, `day`, `weekday`, `weekofyear`, `quarter`, `is_weekend`, `month_start`, `month_end`.
* **Lag features**: `sales_lag_7`, `sales_lag_14`, `sales_lag_30`.
* **Rolling averages**: `rolling_mean_7`, `rolling_mean_30` (computed on shifted target sales to prevent look-ahead leakage).

---

## 3. Train/Test Split

* **Split Strategy**: Chronological 80/20 train/test split.
* **Train Partition**: 718,400 rows (Date Range: 2013-01-31 to 2017-01-06).
* **Test Partition**: 179,600 rows (Date Range: 2017-01-06 to 2017-12-31).
* **Leakage Control**: Zero temporal overlap exists between train and test partitions.

---

## 4. XGBoost Configuration

The serialized best model object (`best_model_v2.pkl`) was inspected and contains the following parameters:
* `max_depth`: 8
* `n_estimators`: 50
* `learning_rate`: 0.1
* `colsample_bytree`: 0.8
* `reg_alpha`: 0.1
* `reg_lambda`: 1.0
* `subsample`: 1.0
* `random_state`: 42
* `objective`: `reg:squarederror`

---

## 5. Evaluation Implementation

* **MAE**: `sklearn.metrics.mean_absolute_error(y_true, y_pred)`
* **RMSE**: `np.sqrt(sklearn.metrics.mean_squared_error(y_true, y_pred))`
* **R²**: `sklearn.metrics.r2_score(y_true, y_pred)`
* **MAPE**: `np.mean(np.abs((y_true - y_pred) / y_true_safe)) * 100` (where zero sales are replaced by `1e-5` to avoid division by zero).
* **Alignment**: The prediction index and target index are aligned 1-to-1 chronologically; no row scrambling occurs.

---

## 6. Result: 6.1748

* **Value**: MAE = 6.1748, RMSE = 8.0365, $R^2$ = 0.9353, MAPE = 12.5866%.
* **Origin**: This is the out-of-sample performance on the test set for the **tuned/optimized XGBoost model** generated by `SalesForecaster.run_forecasting_pipeline()` in `src/train_model.py` after 5-fold TimeSeriesSplit cross-validation.
* **Model File**: `results/models/best_model_v2.pkl`.
* **Status**: **VERIFIED AND REPRODUCIBLE**

---

## 7. Result: 6.2698

* **Value**: MAE = 6.2698, RMSE = 8.1708, $R^2$ = 0.9332, MAPE = 12.7947%.
* **Origin**: This is the out-of-sample performance on the test set for the **fixed-parameter baseline XGBoost model** (default `max_depth = 6`, no alpha/lambda regularization) generated during the 5-model comparison benchmark in `src/model_comparison.py` $\rightarrow$ `ModelComparer.run_benchmark()`.
* **Status**: **VERIFIED AND REPRODUCIBLE**

---

## 8. Source of Discrepancy

The discrepancy arises because two different model configurations were evaluated:
1. **MAE = 6.2698** represents the fixed-hyperparameter baseline XGBoost model (`max_depth = 6`) from the model comparison module (`src/model_comparison.py`).
2. **MAE = 6.1748** represents the optimal tuned XGBoost model (`max_depth = 8`, `colsample_bytree = 0.8`, regularizations) from the training and optimization module (`src/train_model.py`).

*Note*: The manuscript table (Table II) lists the baseline model's MAE of 6.2698, whereas the serialized model saved to disk is the optimized version yielding 6.1748.

---

## 9. Reproducibility Status

* **Status**: Fully reproducible. Running `venv\Scripts\python main.py` executes `ModelComparer.run_benchmark()` (generating the baseline metrics table and saving 6.2698) followed by `SalesForecaster.run_forecasting_pipeline()` (which executes the 5-fold TimeSeriesSplit hyperparameter tuning and outputs 6.1748, saving the final model weights to `results/models/best_model_v2.pkl`).

---

## 10. Verified Baseline for Journal Experiments

The verified baseline for the journal experiments is frozen as the **Tuned XGBoost Regressor (MAE = 6.1748)** since it represents the model configuration that is fully optimized, serialized, and used downstream in the explainability (SHAP) and decision-support engines.

"Journal experiments must use this baseline configuration unless a new experiment explicitly defines a different configuration."
